## 【P3 · 背景 · IPv6 主动测量与 FRP 问题】

先看背景。为什么 IPv6 主动扫描是一个专门的研究方向？关键在于**扫描范式的根本转变**：IPv4 只有 2³² 个地址，ZMap 用 40 分钟就能扫全网；但 IPv6 是 2¹²⁸，物理上不可能穷举，所以所有 IPv6 扫描器都必须依赖一个叫 **TGA (Target Generation Algorithm) 目标生成算法**的组件，比如 6Forest、6Hit、6Graph、DET 这些。而所有 TGA 的效果，都取决于它拿到的那个『种子』（seed）质量。

问题来了，右边这个概念叫 **Fully Responsive Prefix，FRP 全响应前缀**：它是指一个前缀里，你怎么探测都会得到响应——但这些响应不一定来自不同的主机。成因可能是 CDN 负载均衡、蜜罐、NAT 代理池，或者 Linux 那个 `ip_nonlocal_bind` sysctl 让一台机器代所有地址响应。**FRP 会污染 TGA 的训练数据、膨胀 hitlist、浪费探测预算、误导拓扑推断**。所以下面这一栏总结了它为什么重要：识别并剔除 FRP，几乎是所有 IPv6 主动测量任务的前置步骤——是"看清 IPv6 世界"绕不过去的一步。

## 【P4 · 相关工作 · FRP 发现三代技术路线】

FRP 发现这个问题不是新问题，已经有三代技术路线。

**第一代 MAPD / APD**，IMC 2018 提出：思路简单粗暴——把 BGP 表里所有的 /48 前缀枚举一遍，每个前缀随机采 16 个地址探测，都响应就标为 FRP。优点是简单可靠，缺点是**组合爆炸**，长度稍长就跑不动，也做不到任意粒度。

**第二代 Luori**，ICNP 2024，思路升级为**蒙特卡洛树搜索**：把 IPv6 地址空间建成一棵树，逐 nibble 展开。优点是可以任意粒度，缺点是**长度耦合**——每一层的决策依赖上一层，而且每个协议/端口要单独跑一棵树，扩展成本 = N×。

**第三代 Gungnir**，ICNP 2025，就是当前的 SOTA，第一个用生成式 AI 做这个任务的工作。它把 FRP 生成看作**自回归语言建模**——用一个 Transformer decoder，条件在 AS、组织、业务类别、协议端口上，逐 bit 生成 128 位的前缀。相比 Luori，推理快 27 倍，覆盖高 4.2 倍。但是它也有明显问题：**单轴注意力**、注意力二次复杂度 O(L²)，而且是**离线开环**的——训练完就不再调整。

Gungnir 是当前的天花板，但正是它三个"没榨干"的地方，给我们留下了 Heimdall 的机会。

---

## 【P5 · 动机 · Gungnir 尚未解决的三大问题】

我们仔细看 Gungnir 的话，可以总结出三个结构性的欠缺，也就是 PPT 上的 **L1、L2、L3**。

**L1：同 AS 内的信号被浪费。** 我们的实验（下一页会讲）发现同一个 AS 里的 FRP 共享大量的 nibble 分配和前缀长度分布，但 Transformer 的 self-attention 只在**一条前缀内**做，训练时看不到同 AS 的其他 FRP。这是一条**跨样本信号被丢掉了**。

**L2：自注意力二次复杂度。** 输入是 128 bit + 多字段元数据的长序列，自注意力 O(L²)，训练和推理都被拖慢，GPU 内存也不够长上下文用。

**L3：生成是开环的，无法在线纠错。** Gungnir 训练完之后一次性生成全部候选，APD 探测只在事后做粒度修正——错误的模式会**反复重复生成**，直到人工重灌种子。

我们对应地给出三条解决路径：**L1 → 引入 sample-axis 扫描；L2 → 用 Mamba SSM 取代 Attention；L3 → 把开环生成改成闭环。** 这就是 Heimdall 的三大创新。

L1 的判断不是拍脑袋，是有数据支撑的。左边这张图是我们在 21.4 万条种子 FRP 上做的 **pattern entropy** 分析：横轴是模式长度 ℓ（bit），纵轴是熵，虚线是均匀分布的理论上限 log₂ℓ。

这张图直接支撑了我们做 Dual-Scan 的经验依据。

## 【P7 · Heimdall · 三大关键设计】

现在正式进入 Heimdall 的设计。我们的三大创新一一对应刚才的 L1/L2/L3。

**① Dual-Scan Hierarchical Mamba：解决 L1 和 L2。** 每层 DS-HMamba 同时跑两个 Mamba 块——一个沿 128 bit 位轴（within-prefix），一个沿同 AS 样本轴（cross-prefix），再用一个 AS-conditioned gate 融合。底层 Mamba 的 selective scan 是 **O(L) 线性**的，直接把二次复杂度问题干掉。

**② 层次化 MLM · 三阶段生成：对齐 IPv6 分层地址。** IPv6 有天然的三层结构——Coarse [0,32) 路由段、Medium [32,64) 子网段、Fine [64,128) 接口 ID。我们让训练和推理都严格对齐这三层，用**掩码填充**，每阶段并行、非自回归；而且给每一位加一个 Shannon 熵的权重，让模型的容量集中在真正信息量大的 bit 上。**三次前向 vs 128 步自回归**——这就是我们比 Gungnir 快的核心原因。

**③ 闭环在线扫描：解决 L3。** 双向 SeedFilter 做去重和 in-range 丢弃；在线微调把 APD 的正负反馈变成新的训练信号；自适应温度在『卡在已知区』和『发现新贵矿』之间自动切换。

一句话概括：**Transformer 自回归换成 Mamba 双扫描，开环生成换成闭环强化。**

## 【P8 · 系统总览】

## 【P9 · DS-HMamba · Dual-Scan Hierarchical Mamba】

这一页拆解模型细节。

**Outer scan（位轴）**：这一块和 Gungnir 是同一个轴——沿 128 bit 位轴运行标准的 Mamba S6 block。输入依赖的 Δ、A、B、C 参数让扫描是"选择性"的，捕捉的是 bit-by-bit 的位间依赖。复杂度是 O(L·D·N)，对比 Attention 的 O(L²) 是本质提速。

**Inner scan（同 AS 样本轴）**：这是我们的新东西。把一个 batch 里的样本按 AS 分组，同组 Gₐ 个前缀在**每个 bit 位置**分别跑一个 Inner Mamba。它捕捉的是：peer-AS 的 nibble 共享分配、前缀长度分布、子前缀模式——这是 outer scan 看不到的横向信号。单例组（Gₐ=1）时退化为 identity，没有副作用。

**AS-conditioned Gating Fusion**：用元数据条件向量 c 生成一个 softmax gate，把 outer 和 inner 的输出加权融合，再加残差和 LayerNorm。**关键在于 gate 是 AS 条件的** —— 让模型自己学会：这个 AS 更依赖 within-prefix，还是 cross-prefix 结构。

这个 Dual-Scan + Gate 的组合，是**首个在 IPv6 生成任务上引入状态空间模型（SSM）的工作**。

## 【P10 · 训练 · 层次化 MLM 熵加权 · 三阶段推理】

模型定了，接下来讲怎么训练、怎么推理。

上面这个 128-bit 位段图，展示了我们和 RFC 4291 对齐的三层划分：**Coarse [0,32) 路由段、Medium [32,64) 子网段、Fine [64,128) 接口 ID**。

**训练侧（左）**：每一步随机采一个 stage，把对应段替换成 [MASK]，模型重建；**只在前缀长度以内**的位置计 loss。熵加权那块非常关键——BGP 已经锁定的高位 bit 熵低、权重小；后面变化剧烈的 bit 熵高、权重大——**把模型容量集中到真正信息量大的位**。

**推理侧（右）**：从全 mask 开始，先做 BGP lock 固定路由前缀；然后**三次前向**——Coarse fill 一次采 [0,32)，Medium fill 一次采 [32,64)，Fine fill 一次采 [64,128)——每次前向内所有 bit **并行填充**、非自回归；最后按目标长度裁剪。

**3 次前向 replaces 128 步自回归 —— 这就是我们推理速度提升的核心来源。**

## 【P11 · 闭环在线扫描】

这一页讲第三大创新——闭环。一轮闭环是 5 步：**Generate → SeedFilter → APD Probe → Granularity Refine → Online Fine-tune**，然后回到下一轮 Generate。

下面三张卡是三个关键组件：

**双向 SeedFilter**：L1 精确去重（一模一样的直接扔）；L2 是 in-range 静默丢弃——如果候选**严格落在**某条已知种子内，它扩不了 FRP 边界，就直接扔——但是**不产生负样本**，因为它可能确实是 FRP。同时记录『卡在已知区』比例 r_L2，作为温度自适应的信号。反过来，如果候选**覆盖**了已知种子（更宽的前缀），就保留探测。

**在线微调**：APD 的正例和负例分别参与两个 loss，λ=0.1 让模型"讨厌但不禁止"负样本；学习率是预训练的 10%，梯度裁剪，只跑少量 step——让模型跟着环境走但不飘离预训练最优点。

**自适应温度**：如果 L2 比例 > 0.3 或者本轮零发现——说明卡住了，升温探索；如果本轮发现率 > 0.5——降温利用。实验里从任意 T₀∈[0.4,1.0] 起，五轮内温度都会收敛到 0.55 左右——**参数极其鲁棒**。

一句话：**把静态生成变成一个"生成-探测-学习"的强化学习闭环。**

## 【P15 · 运行时间对比】

Heimdall 不光效果好，速度也快。Table 2 是端到端 wall-clock（小时）。

先看 N=1（单协议）：Luori 89.9h、Gungnir 9.3h、Heimdall **5.6h**。
再看 N=5（5 个协议）：Luori 449.5h、Gungnir 19.3h、Heimdall **12.0h**——**相比 Luori 37 倍加速，相比 Gungnir 也有 1.6 倍加速**。

加速来源有三点：**① 预训练 1.7× 加速**——Mamba 选择性扫描 O(L) 干掉了 Transformer 的 O(L²)；**② 每协议推理 1.5× 加速**——3 次并行掩码填充 vs 128 步自回归；**③ 多协议摊薄**——预训练一次可服务多协议。

**更强的效果 + 更快的速度 = Pareto dominance**，没有 trade-off。

## 【P17 · 长期观测 · 3 个月 · 23 协议多轮扫描】

论文里我们额外做了一个大规模纵向研究——**Heimdall 连续跑了 3 个月，覆盖 23 个活跃协议**。相比公开的 IPv6 hitlist 和 Luori 的 FRP list，Cov_AS 从 335/530 涨到 **684**，Cov_Routing 从 3237/7324 涨到 **9512**。三个非常有意思的发现：

**① 集中度**：Cloudflare、Amazon、Akamai 三家组织贡献了超过 200 万条 ICMPv6 FRP，以 /64 – /56 细粒度为主——这和 `ip_nonlocal_bind` 大规模绑定的行为完全一致。

**② 服务 vs 端口错配**：1.6M 条 HTTP-FRP 地址里，**只有 15% 真的返回 HTTP 内容**，其余 85% 只是在 TCP 层响应但没有应用——我们推测这是绕过 per-IP 限流的**出向代理池**，副作用就是让单 IP 级别的 DDoS 防御失效。

**③ 安全信号**：SSH-FRP 中约 11% 保留 OpenSSH 7.2p2 的老 KEX 算法——**强烈疑似蜜罐**；SSL-FRP 中约 23% 共用一张 Cloudflare 泛证书——**一旦私钥泄漏，这一整批 FRP 集体暴露**。

**FRP 不只是测量噪声，它本身就是 IPv6 生态里 CDN、蜜罐、代理的一个观察窗口。**

## 【P18 · Ethics & 总结】

**Ethics（左）**：我们严格遵循 Menlo Report 和社区的 ethical measurement 指南——单一 vantage point、速率 ≤1Mbps、随机化目标顺序、单批 ≤10 分钟；维护 opt-out list 并 24 小时内响应；**从不做渗透测试**，只从 banner 推断，绝不对活主机做漏洞验证。

**总结（右）**：一句话总结 Heimdall 的贡献 ——
- **方法**：首次把 SSM/Mamba 引入 IPv6 生成任务；
- **结构**：Dual-Scan 双轴 + AS-gate 融合；
- **训练**：层次化 MLM + 熵加权 + 三阶段并行推理；
- **闭环**：双向 SeedFilter + 在线微调 + 温度自适应；
- **结果**：1.9× 吞吐、1.2× AS 覆盖、1.7× 训练加速；
- **开源**：代码和 curated FRP list 计划公开。

**Dual-Scan × Closed-Loop × Linear-time SSM = 下一代 IPv6 主动测量的技术底座。**
